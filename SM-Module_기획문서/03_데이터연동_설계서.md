## 1. 연동 아키텍처

│  │  (MariaDB)        │       │  (Oracle ERP)         │  │
│  │  HikariCP Pool    │       │  HikariCP Pool        │  │
│  └────────┬─────────┘       └──────────┬───────────┘  │
│           │                            │              │
│  ┌────────┴─────────┐       ┌──────────┴───────────┐  │
│  │  JPA / Hibernate  │       │  JdbcTemplate         │  │
│  │  (Entity 기반)    │       │  (SQL 직접 실행)      │  │
│  └──────────────────┘       └──────────────────────┘  │
│                                                        │
│  ┌────────────────────────────────────────────────┐   │

| 항목 | 설명 |
|------|------|
| 연동 프로토콜 | JDBC (Oracle Thin Driver) |

| 인증 | COMET 계정 |
| 회사코드 | 1000 (WHERE COMPANY_CD = '1000') |

| 쿼리 방식 | JdbcTemplate (Native SQL) |

## 2. 데이터 매핑

### 2.1 거래처 매핑

| SM Module (business_owners) | ERP (CI_PARTNER_MST) | 매핑 방향 | 비고 |
|----------------------------|---------------------|----------|------|
| company_name | PARTNER_NM | ERP → SM | 거래처명 |
| biz_no | BIZR_NO | ERP → SM | 사업자등록번호 |
| douzone_code | **PARTNER_CD** | **연결키** | ERP 거래처코드 |
| representative_name | CEO_NM | ERP → SM | 대표자명 |
| address | BASE_ADDR + DTL_ADDR2 | ERP → SM | 주소 |
| - | PARTNER_FG_CD | - | 거래처유형 (1:매출처) |
| - | USE_YN | - | 사용여부 필터 |

> **매핑 규칙**: SM `business_owners.douzone_code` = ERP `CI_PARTNER_MST.PARTNER_CD`로 연결
> CI_PARTNER_MST는 COMPANY_CD 없는 전사 공통 테이블 (46,361건, 사용중 41,414건)

## 3. 연동 시나리오 상세

### 3.1 ERP → SM Module (읽기 동기화)

#### R1. 거래처 마스터 동기화

```
트리거: 매일 02:00 (Cron 스케줄)
소스:   CI_PARTNER_MST (USE_YN = 'Y')
대상:   business_owners
연결키: PARTNER_CD = douzone_code
처리:
  1. ERP에서 USE_YN='Y' 거래처 조회
  2. SM에 해당 douzone_code 존재 여부 확인
  3. 존재하면 UPDATE, 없으면 INSERT
  4. SM에만 있고 ERP에 없는 건은 유지 (삭제하지 않음)
```

#### R2. 품목 마스터 동기화

```
트리거: 매일 02:00 (Cron 스케줄)
소스:   CI_ITEM (USE_YN = 'Y')
처리:   품목코드/품목명 매핑 테이블 갱신
```

#### R3. 사원/부서 동기화

```
트리거: 매일 02:00 (Cron 스케줄)
소스:   HR_EMP_MST (HLOF_FG_CD = '1' 재직자), VW_MA_DEPT_MST
연결키: EMP_NO = employee_no, DEPT_CD
처리:   사원 정보 및 부서 정보 갱신
```

#### R4. 수주 현황 동기화

```
트리거: 매시 정각 (1시간 간격)
소스:   SD_SO_MST + SD_SO_DTL (WHERE UPDATE_DTS >= 마지막동기화시각)
처리:   수주 현황 데이터 갱신 (대시보드/통계용)
```

#### R5. 출하 현황 동기화

```
트리거: 매시 정각
소스:   SD_DLV_MST + SD_DLV_DTL (변경분)
처리:   출하 현황 갱신 (프로세스 흐름 추적용)
```

#### R6. 매출(청구) 동기화

```
트리거: 매시 정각
소스:   SD_BILL_MST + SD_BILL_DTL (변경분)
처리:   매출 데이터 갱신, 대시보드 반영
```

### 3.2 SM Module → ERP (쓰기)

#### W1. 주문 등록

```
트리거: SM Module에서 주문 생성 시
대상:   SD_ORDER_MST_X20329 + SD_ORDER_DTL_X20329
처리:
  1. SM 주문 데이터 → ERP 컬럼 매핑
  2. ORDDOC_NO 채번 (GOR + 날짜 + 순번)
  3. SD_ORDER_MST_X20329 INSERT
  4. SD_ORDER_DTL_X20329 INSERT (품목별)
  5. 성공 시 SM orders.erp_order_no 업데이트
  6. 실패 시 재시도 큐(integration_retry_queue) 등록
```

#### W2. 주문 수정

```
트리거: SM Module에서 주문 수정 시
대상:   SD_ORDER_MST_X20329 + SD_ORDER_DTL_X20329
처리:
  1. erp_order_no로 기존 ERP 주문 조회
  2. 변경된 필드만 UPDATE
  3. 상세 항목은 DELETE + INSERT (전체 교체)
```

#### W3. 주문 상태 변경

```
트리거: SM Module에서 상태 변경 시
대상:   SD_ORDER_MST_X20329.WRK_FG
처리:   상태 코드 매핑 후 UPDATE
```

#### W4. 외주발주

```
트리거: SM Module에서 외주발주 확정 시
대상:   PU_PURORDER_MST + PU_PURORDER_DTL
처리:
  1. PURDOC_NO 채번 (PUR + 날짜 + 순번)
  2. PU_PURORDER_MST INSERT
  3. PU_PURORDER_DTL INSERT (품목별)
```

## 4. 연동 핵심 조인키

| 연동 대상 | SM Module 키 | ERP 키 | ERP 테이블 |

| 거래처 | douzone_code | PARTNER_CD | CI_PARTNER_MST |
| 사원 | employee_no | EMP_NO / BIZRSPT_EMPNO_CD | HR_EMP_MST |
| 부서 | department.code | DEPT_CD | VW_MA_DEPT_MST |

| 출하 | - | DLVDOC_NO | SD_DLV_MST |
| 매출 | - | BILLDOC_NO | SD_BILL_MST |
| 발주 | po_no | PURDOC_NO | PU_PURORDER_MST |

## 5. 에러 처리 및 재시도

### 5.1 재시도 정책

| 상황 | 처리 |
|------|------|
| Oracle 연결 실패 | 30초 후 재시도, 최대 3회 |
| INSERT/UPDATE 실패 | `integration_retry_queue` 테이블에 등록 |
| 재시도 큐 처리 | 5분 간격 스케줄러로 미처리 건 재시도 |
| 최대 재시도 초과 | 관리자 알림 (이메일/대시보드 표시) |

### 5.2 데이터 정합성

| 원칙 | 설명 |
|------|------|
| ERP 우선 | 마스터 데이터(거래처/품목/사원)는 ERP가 원본 |
| SM 우선 | SM에서 생성한 주문/발주는 SM이 원본 |
| 충돌 시 | 최신 UPDATE_DTS 기준 적용 |
| 감사 로그 | 모든 연동 이력을 로그 테이블에 기록 |
