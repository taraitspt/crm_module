1. 인터페이스 개요

1.1 연동 구성도

SM Module과 Oracle ERP(iCUBE) 간의 전체 데이터 연동 구성을 나타냅니다.

SM Module
MariaDB
  • orders
  • business_owners
  • users
  • departments
  • sales
  • outsourcing_pos
←←← 마스터 동기화 (배치)
←←← 트랜잭션 조회 (배치)
→→→ 주문 등록/수정 (실시간)
→→→ 외주발주 등록 (실시간)
→→→ 매출 확정 반영 (실시간)
Oracle ERP
iCUBE
  • SD_ORDER_MST
  • CI_PARTNER_MST
  • HR_EMP_MST
  • VW_MA_DEPT_MST
  • SD_BILL_MST
  • PU_PURORDER_MST
범례: ← ERP → SM 읽기 (마스터 데이터 및 트랜잭션 조회)   |   → SM → ERP 쓰기 (주문 생성/수정, 외주발주 등록)

2. 인터페이스 상세 (읽기: ERP → SM)

IF-001 | 거래처 마스터 동기화

SYNC
IF ID IF-001
인터페이스명 거래처 마스터 동기화
방향 ERP → SM (읽기/동기화)
소스 테이블 CI_PARTNER_MST (Oracle, 46,361건)
대상 테이블 business_owners (MariaDB)
연결키 PARTNER_CD = douzone_code
연동방식 배치 (Spring @Scheduled)
주기 매일 02:00 (Cron: 0 0 2 * * ?)
조건 USE_YN = 'Y' AND PARTNER_FG_CD IN ('1','2','3')

필드 매핑

ERP 컬럼 ERP 타입 SM 컬럼 SM 타입 변환규칙
PARTNER_CD VARCHAR2(80) → douzone_code VARCHAR(20) 그대로
PARTNER_NM VARCHAR2(600) → company_name VARCHAR(200) TRIM
BIZR_NO VARCHAR2(80) → biz_no VARCHAR(20) 하이픈 제거
CEO_NM VARCHAR2(400) → representative_name VARCHAR(50) TRIM
BASE_ADDR + DTL_ADDR2 VARCHAR2(800+400) → address VARCHAR(500) 공백 연결
TEL_NO VARCHAR2(200) → representative_phone VARCHAR(20) 그대로
BIZC_NM VARCHAR2(200) → biz_item VARCHAR(100) TRIM
BIZTP_NM VARCHAR2(200) → biz_type VARCHAR(100) TRIM

소스 SQL

SELECT PARTNER_CD, PARTNER_NM, BIZR_NO, CEO_NM,
       BASE_ADDR, DTL_ADDR2, TEL_NO, FAX_NO,
       BIZC_NM, BIZTP_NM, PARTNER_FG_CD, USE_YN
FROM CI_PARTNER_MST
WHERE USE_YN = 'Y'

처리 로직

  1. ERP에서 전체 활성 거래처 조회
  2. SM에서 douzone_code로 기존 거래처 조회
  3. 매칭 시: UPDATE (이름, 주소, 연락처 등 갱신)
  4. 미매칭 시: INSERT (신규 거래처 등록)
  5. 동기화 이력 erp_sync_logs에 기록
참고: 거래처 수가 약 46,000건으로 다량이므로, 배치 사이즈 1,000건 단위로 분할 처리하며, 전체 동기화 소요 시간은 약 3~5분입니다.

IF-005 | 주문 현황 조회

READ
IF ID IF-005
인터페이스명 주문 현황 조회
방향 ERP → SM (읽기)
소스 테이블 SD_ORDER_MST_X20329 + SD_ORDER_DTL_X20329 (Oracle)
대상 SM 화면 조회용 (직접 저장하지 않음)
연동방식 배치 (Spring @Scheduled)
주기 1시간 (Cron: 0 0 * * * ?)
변경분 조건 UPDATE_DTS >= :lastSyncTime

소스 SQL

SELECT m.ORDDOC_NO, m.ORD_DT, m.ORDDOC_NM,
       m.PARTNER_CD, m.DEPT_CD, m.BIZRSPT_EMPNO_CD,
       m.WRK_FG, m.RMK_TXT,
       d.ORDDOC_SQ, d.ITEM_CD, d.ITEM_NM,
       d.ORD_QT, d.SELL_AMT, d.SUM_AMT,
       d.LACO_AMT, d.MTRIL_AMT, d.TAX_AMT, d.ORDDOC_ST
FROM SD_ORDER_MST_X20329 m
JOIN SD_ORDER_DTL_X20329 d
  ON m.COMPANY_CD = d.COMPANY_CD
  AND m.ORDDOC_NO = d.ORDDOC_NO
WHERE m.COMPANY_CD = '1000'
  AND m.UPDATE_DTS >= :lastSyncTime
ORDER BY m.UPDATE_DTS DESC

주요 컬럼 설명

ERP 컬럼 설명 비고
ORDDOC_NO주문번호GOR + YYYYMMDD + 순번
ORD_DT주문일자YYYYMMDD
ORDDOC_NM주문명
PARTNER_CD거래처 코드CI_PARTNER_MST 참조
WRK_FG진행상태코드값 (erp_code_mappings)
ORDDOC_SQ상세 순번1부터 순차
ITEM_NM품목명
ORD_QT주문수량
SUM_AMT합계금액

처리 로직

  1. 마지막 동기화 시각 이후 변경된 주문 조회
  2. SM 주문 목록과 비교하여 상태 갱신 반영
  3. ERP에서 변경된 주문 상태를 SM orders.erp_status에 반영
  4. 동기화 시각 업데이트

IF-009 | 주문 등록

WRITE
IF ID IF-009
인터페이스명 주문 등록
방향 SM → ERP (쓰기)
소스 orders + order_works + order_items (MariaDB)
대상 SD_ORDER_MST_X20329 + SD_ORDER_DTL_X20329 (Oracle)
트리거 SM 주문 생성 이벤트 (실시간)
채번규칙 ORDDOC_NO = 'GOR' + YYYYMMDD + 5자리순번 (예: GOR2026032400001)

필드 매핑 (MST - 마스터)

SM 컬럼 SM 값 (예시) ERP 컬럼 변환규칙
- '1000' → COMPANY_CD 고정값
order_no GOR... → ORDDOC_NO 채번
received_date 2026-03-24 → ORD_DT YYYYMMDD 변환
title 주문명 → ORDDOC_NM 그대로
biz_owner.douzone_code P00123 → PARTNER_CD 매핑
department.code 4400 → DEPT_CD 매핑
sales_manager.employee_no 10011275 → BIZRSPT_EMPNO_CD 매핑
status PRINTING → WRK_FG 코드 매핑 (erp_code_mappings)
note 비고 → RMK_TXT 그대로

필드 매핑 (DTL - 상세)

SM 컬럼 ERP 컬럼 변환규칙
order_item.item_name → ITEM_NM 그대로
order_item.category → ITEM_FG 코드 매핑
order_item.quantity → ORD_QT 그대로
order_item.unit_price → ITEM_UM 그대로
order_item.subtotal → SUM_AMT 그대로
(순번) → ORDDOC_SQ 1부터 순차
- → ORDDOC_ST '0' (미확정)

ERP INSERT SQL

-- 마스터 INSERT
INSERT INTO SD_ORDER_MST_X20329 (
    COMPANY_CD, ORDDOC_NO, PLANT_CD, ORD_DT,
    ORDDOC_NM, PARTNER_CD, DEPT_CD, BIZRSPT_EMPNO_CD,
    WRK_FG, RMK_TXT, INSERT_DTS, UPDATE_DTS
) VALUES (
    '1000', :orderNo, '1000', :ordDt,
    :orderNm, :partnerCd, :deptCd, :empNo,
    :wrkFg, :rmkTxt, SYSDATE, SYSDATE
);

-- 상세 INSERT (건별)
INSERT INTO SD_ORDER_DTL_X20329 (
    COMPANY_CD, ORDDOC_NO, ORDDOC_SQ, PLANT_CD,
    ITEM_NM, ITEM_FG, ORD_QT, ITEM_UM, SUM_AMT,
    ORDDOC_ST, INSERT_DTS, UPDATE_DTS
) VALUES (
    '1000', :orderNo, :seq, '1000',
    :itemNm, :itemFg, :ordQt, :itemUm, :sumAmt,
    '0', SYSDATE, SYSDATE
);

처리 로직

  1. SM 주문 데이터 조회
  2. ORDDOC_NO 채번 (GOR + YYYYMMDD + 순번)
  3. 거래처/사원/부서 매핑키 변환
  4. SD_ORDER_MST_X20329 INSERT
  5. SD_ORDER_DTL_X20329 INSERT (품목별)
  6. 성공 시: SM orders.erp_order_no 업데이트
  7. 실패 시: integration_retry_queue에 등록
주의: ERP INSERT 시 트랜잭션 관리가 필수입니다. MST와 DTL은 반드시 하나의 트랜잭션으로 처리하며, 부분 실패 시 전체 롤백합니다.

4.3 데이터 정합성 규칙

규칙 설명
마스터 데이터 원본 ERP가 Single Source of Truth. SM은 사본(Replica)을 유지합니다.
트랜잭션 원본 SM에서 생성한 주문은 SM이 원본입니다. ERP는 수신 데이터로 처리합니다.
충돌 해결 UPDATE_DTS가 더 최신인 데이터가 우선 적용됩니다.
삭제 정책 SM에만 존재하는 거래처는 유지합니다 (삭제하지 않음). ERP에서 비활성(USE_YN='N')된 거래처는 SM에서도 비활성 처리합니다.
동기화 이력 모든 연동 작업을 erp_sync_logs 테이블에 기록합니다. (인터페이스 ID, 실행시각, 처리건수, 성공/실패 여부, 에러 메시지)
중요: 데이터 정합성 이슈 발생 시, 마스터 데이터는 ERP 기준으로 SM 데이터를 갱신하고, 트랜잭션 데이터는 SM 기준으로 ERP 데이터를 갱신합니다. 양방향 충돌 발생 시 UPDATE_DTS 기준으로 최신 데이터를 우선 적용하며, 관리자에게 알림을 발송합니다.

5. 신규 설계 기준 인터페이스 매핑

기존 SM Module의 테이블 구조를 ERP 연동에 최적화된 신규 스키마로 재설계하였습니다. 아래는 신규 SM 테이블 기준의 ERP 인터페이스 매핑 정의입니다.

설계 원칙: 신규 SM 스키마는 ERP의 복합 PK 구조(company_cd, plant_cd)를 그대로 채택하여, 인터페이스 변환 로직을 최소화하고 데이터 정합성을 보장합니다. 기본값은 company_cd=1000, plant_cd=1000입니다.

5.3 설계 참고사항

복합 PK 설계 (ERP 정렬): 신규 SM 스키마의 모든 트랜잭션 테이블(order_mst, order_dtl, po_mst, po_dtl, sales_mst, sales_dtl, goal_mst)은 company_cd + plant_cd를 PK의 선행 컬럼으로 포함합니다. 이는 ERP(iCUBE)의 COMPANY_CD + PLANT_CD 구조와 동일하며, 향후 다중 회사/공장 확장 시에도 인터페이스 변경 없이 대응 가능합니다.
ERP 동기화 상태 추적: 신규 스키마에는 ERP 연동 결과를 추적하기 위한 상태 필드가 포함되어 있습니다.
  • sales_mst.erp_sync_status - 더존 ERP 연동 상태 (PENDING / SYNCED / FAILED)
  • po_settle_mst.gitgo_sync_status - 깃고(외주정산시스템) 연동 상태 (PENDING / SYNCED / FAILED)
기존에는 별도의 erp_sync_logs 테이블에서만 추적했으나, 신규 설계에서는 개별 레코드 수준에서 동기화 상태를 관리하여 재시도 및 오류 추적이 용이합니다.
마스터/디테일 분리 패턴: 신규 SM 스키마는 ERP의 MST/DTL 구조를 그대로 반영하여 인터페이스 매핑을 단순화합니다.
SM 마스터 SM 디테일 ERP 마스터 ERP 디테일
order_mst order_dtl + order_info SD_ORDER_MST_X20329 SD_ORDER_DTL_X20329
po_mst po_dtl PU_PURORDER_MST PU_PURORDER_DTL
sales_mst sales_dtl SD_BILL_MST SD_BILL_DTL
po_settle_mst po_settle_dtl (깃고 연동 - ERP 직접 대응 없음)
기존에는 orders(단일), outsourcing_pos(단일), sales(단일) 구조였으나, ERP와 구조를 정렬함으로써 INSERT/UPDATE 시 필드 변환 로직이 대폭 감소합니다.
마이그레이션 참고: 기존 테이블(Section 2~3에서 정의한 business_owners, orders, outsourcing_pos, sales 등)의 데이터는 신규 스키마로 마이그레이션이 필요합니다. 기존 인터페이스(IF-001 ~ IF-013)는 마이그레이션 완료 후 신규 인터페이스(NIF-001 ~ NIF-007)로 순차 전환합니다.
