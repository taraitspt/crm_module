1. 문서 개요

본 문서는 SM Module - Oracle ERP 연동 프로젝트의 요구사항을 정의한 문서입니다. 기존 SM Module(MariaDB 기반)과 고객사 Oracle ERP(iCUBE) 시스템 간의 데이터 연동에 필요한 기능 요구사항 및 비기능 요구사항을 체계적으로 정리하여, 개발팀과 이해관계자 간의 명확한 합의 기준을 제공합니다.

본 요구사항 정의서는 Phase 1(환경 구성) ~ Phase 5(대시보드 연동)까지의 전체 개발 범위를 포괄하며, 우선순위에 따라 단계적으로 구현됩니다.

3. 비기능 요구사항

요구사항 ID 구분 요구사항명 상세 설명 측정 기준 우선순위
NFR-001 성능 마스터 동기화 처리 시간 마스터 데이터 전체 동기화(거래처 46,361건 + 품목 38,169건 + 사원 2,402건 + 부서 96건)가 10분 이내에 완료되어야 한다 동기화 소요시간 < 600초 상
NFR-002 성능 트랜잭션 조회 응답시간 ERP 데이터 조회 API(주문/수주/출하/매출)가 3초 이내에 응답해야 한다 API 응답시간 < 3000ms 상
NFR-003 성능 커넥션 풀 제한 Oracle 커넥션 풀을 최대 5개로 제한하여 ERP DB 부하를 최소화한다 HikariCP max-pool-size: 5 상
NFR-004 가용성 Oracle 장애 격리 Oracle 연결 실패 시에도 SM Module의 기본 기능(MariaDB 기반)이 정상 동작해야 한다 Oracle 장애 시 SM 정상 여부 상
NFR-005 가용성 재시도 메커니즘 Oracle 연결 실패 시 30초 후 재시도, 최대 3회. 모두 실패 시 관리자 알림 재시도 횟수 및 간격 상
NFR-006 보안 DB 접속정보 암호화 Oracle 접속 비밀번호를 application.yml에 평문으로 저장하지 않는다. Jasypt 또는 환경변수 사용 설정파일 점검 상
NFR-007 보안 네트워크 접근제어 EC2 → Oracle 통신은 방화벽으로 허용된 IP(3.35.116.156)만 접속 가능하도록 한다 방화벽 규칙 확인 상
NFR-008 데이터 데이터 정합성 마스터 데이터는 ERP를 원본(Single Source of Truth)으로 한다. 트랜잭션 충돌 시 최신 UPDATE_DTS 기준 적용 동기화 전후 건수 비교 상
NFR-009 데이터 감사 추적 모든 ERP 연동 작업(동기화, INSERT, UPDATE)의 실행일시, 결과, 처리건수, 소요시간을 로그에 기록한다 로그 테이블 기록 여부 중
NFR-010 운영 동기화 모니터링 동기화 상태(마지막 실행, 성공/실패, 처리건수)를 관리 화면 또는 대시보드에서 확인할 수 있어야 한다 관리 화면 제공 여부 중

6. 참고: 신규 DB 설계 반영사항

신규 타겟 DB 스키마(14개 테이블)가 상기 요구사항을 어떻게 지원하는지 정리합니다. (참고: dbdiagram.io 스키마)

# 설계 반영사항 상세 설명 관련 요구사항
1 company_cd + plant_cd 복합키 신규 설계 스키마에서 모든 테이블은 company_cd + plant_cd 복합키를 선두 컬럼으로 사용하여 ERP 멀티컴퍼니/멀티플랜트 구조와 정렬됩니다. 이를 통해 ERP 데이터와의 1:1 키 매핑이 가능합니다. 전체 요구사항
2 order → order_mst/dtl/info 마스터-디테일 분리 주문 데이터를 order_mst(마스터) → order_dtl(디테일) → order_info(상세사양) 3계층으로 분리하여 ERP SD_ORDER_MST/DTL_X20329 구조와 1:1 대응합니다. 추가로 order_dlv(납품)와 file_info(첨부파일)가 연결됩니다. 이를 통해 주문 등록/수정/조회 시 ERP 테이블과 직접 매핑 가능합니다. FR-R-001, FR-R-002, FR-R-003, FR-R-004
FR-W-001, FR-W-002, FR-W-003
3 goal_mst 통합 테이블 goal_mst 단일 테이블로 파트목표/AM목표를 통합합니다. field_cd 컬럼(내부/외부)으로 구분하며, PK는 company_cd + plant_cd + plan_yy + plan_mm + dept_cd + sales_emp_id + field_cd입니다. 이를 통해 FR-U-001 요구사항(목표입력 화면 통합)이 DB 레벨에서 지원됩니다. FR-U-001
4 sales_mst.erp_sync_status sales_mst 테이블의 erp_sync_status 필드(ENUM: PENDING/SYNCED/FAILED)를 통해 매출확정 후 ERP 반영 상태를 추적할 수 있습니다. 매출확정 시 SM → ERP 쓰기 결과를 이 필드에 기록하여 동기화 상태를 관리합니다. FR-W-005
5 po_settle_mst.gitgo_sync_status po_settle_mst 테이블의 gitgo_sync_status 필드(ENUM: PENDING/SYNCED/FAILED)를 통해 외주정산의 깃고(전자결재) 연동 상태를 추적할 수 있습니다. 정산 생성 후 깃고 매입정산 결과를 이 필드에 기록하여 프로세스 진행 상황을 관리합니다. FR-W-004 (관련)
참고: 신규 타겟 스키마는 총 14개 테이블(users, departments, order_mst, order_dtl, order_info, order_dlv, file_info, po_mst, po_dtl, po_settle_mst, po_settle_dtl, sales_mst, sales_dtl, goal_mst)로 구성됩니다. 기존 SM Module의 단일 테이블 구조를 ERP 정합성 중심의 마스터-디테일 구조로 재설계하여, ERP 연동 시 데이터 변환 없이 직접 매핑이 가능합니다.
