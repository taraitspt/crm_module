## 1. 구현 단계 (Phase)

### Phase 1: Oracle 연결 기반 구축

**목표**: Spring Boot 애플리케이션에서 Oracle ERP 데이터베이스에 안정적으로 접속

| # | 작업 | 상세 |
|---|------|------|
| 1-1 | Oracle JDBC 드라이버 추가 | `ojdbc11` (Oracle 19c 호환) Maven/Gradle 의존성 추가 |
| 1-2 | 듀얼 데이터소스 설정 | Primary: MariaDB (기존), Secondary: Oracle (신규) |
| 1-3 | Oracle JdbcTemplate 설정 | `@Qualifier("oracleJdbcTemplate")` 빈 등록 |
| 1-4 | 연결 테스트 API | `/api/erp/health` 엔드포인트로 Oracle 접속 확인 |
| 1-5 | application-prod.yml 설정 | Oracle 접속 정보, HikariCP 풀 설정 |

**설정 예시**:
```yaml
erp:
  datasource:
    url: jdbc:oracle:thin:@39.125.168.136:15253:erp10
    username: COMET
    password: (암호화 처리)
    driver-class-name: oracle.jdbc.OracleDriver
    hikari:
      maximum-pool-size: 5
      minimum-idle: 2
      connection-timeout: 30000
      idle-timeout: 600000
  company-code: "1000"
```

**산출물**: Oracle 접속 가능한 Spring Boot 설정

### Phase 2: 마스터 데이터 동기화 (ERP → SM)

**목표**: ERP의 거래처/품목/사원/부서 마스터를 SM Module에 동기화

| # | 작업 | 소스 테이블 | SM 대상 | 동기화 주기 |
|---|------|-----------|---------|------------|
| 2-1 | 거래처 동기화 | CI_PARTNER_MST | business_owners | 매일 02:00 |
| 2-2 | 품목 매핑 테이블 | CI_ITEM | (신규 매핑 테이블) | 매일 02:00 |
| 2-3 | 사원 동기화 | HR_EMP_MST | users | 매일 02:00 |
| 2-4 | 부서 동기화 | VW_MA_DEPT_MST | departments | 매일 02:00 |
| 2-5 | 매핑 코드 테이블 | - | erp_code_mappings (신규) | - |

**주요 SQL**:
```sql
-- 거래처 조회
SELECT PARTNER_CD, PARTNER_NM, BIZR_NO, CEO_NM,
       BASE_ADDR, DTL_ADDR2, TEL_NO, FAX_NO,
       PARTNER_FG_CD, USE_YN
FROM CI_PARTNER_MST
WHERE USE_YN = 'Y';

-- 재직 사원 조회
SELECT e.EMP_NO, e.KOR_NM, e.DEPT_CD, d.DEPT_NM,
       e.POSI_CD, e.PSTN_CD
FROM HR_EMP_MST e
LEFT JOIN VW_MA_DEPT_MST d
  ON e.COMPANY_CD = d.COMPANY_CD AND e.DEPT_CD = d.DEPT_CD
WHERE e.COMPANY_CD = '1000'
  AND e.HLOF_FG_CD = '1';

-- 부서 조회
SELECT DEPT_CD, DEPT_NM, UP_DEPT_CD, UP_DEPT_NM,
       DEPT_LV, BIZAREA_CD, BIZAREA_NM
FROM VW_MA_DEPT_MST
WHERE COMPANY_CD = '1000';
```

**산출물**: 마스터 데이터 자동 동기화 기능, 매핑 테이블

### Phase 3: 트랜잭션 데이터 동기화 (ERP → SM)

**목표**: ERP의 수주/출하/매출 데이터를 SM Module에서 조회 가능하도록 구현

| # | 작업 | 소스 테이블 | 동기화 주기 | 용도 |
|---|------|-----------|------------|------|
| 3-1 | 주문 현황 조회 | SD_ORDER_MST/DTL_X20329 | 1시간 | 주문목록, 주문상세 |
| 3-2 | 수주 현황 조회 | SD_SO_MST/DTL | 1시간 | 대시보드, 통계 |
| 3-3 | 출하 현황 조회 | SD_DLV_MST/DTL | 1시간 | 프로세스 흐름 |
| 3-4 | 매출 현황 조회 | SD_BILL_MST/DTL | 1시간 | 매출목록, 대시보드 |
| 3-5 | 매출계획 조회 | SD_MMBLPL_MST_X20329 | 1일 | 목표 대비 실적 |
| 3-6 | 매출채권 조회 | SD_ARSUMM_MST | 1시간 | 통계 |

**주요 SQL**:
```sql
-- 최근 주문 변경분 조회
SELECT m.ORDDOC_NO, m.ORD_DT, m.ORDDOC_NM,
       m.PARTNER_CD, m.DEPT_CD, m.BIZRSPT_EMPNO_CD, m.WRK_FG,
       d.ITEM_CD, d.ITEM_NM, d.ORD_QT, d.SELL_AMT, d.SUM_AMT
FROM SD_ORDER_MST_X20329 m
JOIN SD_ORDER_DTL_X20329 d
  ON m.COMPANY_CD = d.COMPANY_CD AND m.ORDDOC_NO = d.ORDDOC_NO
WHERE m.COMPANY_CD = '1000'
  AND m.UPDATE_DTS >= :lastSyncTime;

-- 매출 현황
SELECT m.BILLDOC_NO, m.BILL_DT, m.SALEPRTN_CD,
       m.TRAN_AMT, m.SPLY_AMT, m.TAX_AMT, m.BILL_ST
FROM SD_BILL_MST m
WHERE m.COMPANY_CD = '1000'
  AND m.UPDATE_DTS >= :lastSyncTime;

-- 월별 매출 계획 (목표)
SELECT PLAN_YY, DEPT_CD, EMP_NO, FG_CD,
       MM1_LACO_GOAL_AMT, MM2_LACO_GOAL_AMT, ..., MM12_LACO_GOAL_AMT,
       MM1_MTRIL_GOAL_AMT, MM2_MTRIL_GOAL_AMT, ..., MM12_MTRIL_GOAL_AMT
FROM SD_MMBLPL_MST_X20329
WHERE COMPANY_CD = '1000';
```

**산출물**: 트랜잭션 데이터 조회/동기화 기능, 대시보드 데이터 연동

### Phase 4: SM Module → ERP 쓰기

**목표**: SM Module에서 등록/수정한 데이터를 ERP에 반영

| # | 작업 | 대상 테이블 | 트리거 |
|---|------|-----------|--------|
| 4-1 | 주문 등록 → ERP | SD_ORDER_MST/DTL_X20329 | 주문 생성 시 |
| 4-2 | 주문 수정 → ERP | SD_ORDER_MST/DTL_X20329 | 주문 수정 시 |
| 4-3 | 주문 상태변경 → ERP | SD_ORDER_MST_X20329.WRK_FG | 상태 변경 시 |
| 4-4 | 외주발주 → ERP | PU_PURORDER_MST/DTL | 발주 확정 시 |
| 4-5 | 매출확정 → ERP | SD_BILL_MST | 매출 확정 시 |
| 4-6 | 재시도 큐 처리 | integration_retry_queue | 5분 간격 |

**산출물**: 양방향 연동 완성, 재시도 메커니즘
